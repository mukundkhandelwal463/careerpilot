📌 Project Introduction & Problem Context

In the contemporary recruitment landscape, both job seekers and HR professionals face a significant “visibility gap.” Candidates often struggle with the opacity and rigid keyword algorithms of modern Applicant Tracking Systems (ATS), while recruiters are inundated with overwhelming volumes of incoming resumes, rendering manual evaluation nearly impossible. This project presents CareerPilot, an AI-powered candidate career acceleration and resume evaluation platform engineered to bridge this gap. By integrating a deterministic scikit-learn TF-IDF similarity vectorizer with Google’s Gemini Generative AI, the system delivers objective 0–100% ATS scorecards, granular keyword-gap diagnostics, an executive browser-based LaTeX resume architect, real-time AI voice and written mock interviews, and personalized career roadmaps — transforming an otherwise static resume into an intelligent, data-driven career preparation suite.

The platform’s core intelligence is governed by a robust hybrid scoring engine: a Model1 TF-IDF cosine-similarity vectorizer establishes the deterministic mathematical foundation, while the Google Gemini 2.5 Flash API layer supplies contextual semantic evaluations, missing-skill extractions, and stream-specific technical keyword recommendations. Beyond resume screening, CareerPilot incorporates an end-to-end placement readiness ecosystem. This includes a dedicated Computer Science Special Hub covering high-yield theory cards for Operating Systems, Database Management Systems, Computer Networks, System Design, and Object-Oriented Programming; a Top-260 DSA Mastery Tracker organizing curated algorithmic patterns; an interactive AI Voice Mock Interview Hub evaluating technical accuracy (70%), structure (20%), and speech fluency (10%); a real-time Live Job Matcher indexing 100K+ technical roles; and a centralized Candidate Analytics Dashboard with 1-click diagnostic PDF export capabilities — all seamlessly rendered through a reactive React 19 / Vite 7 single-page application communicating over REST with a modular, 6-app Django 5.x backend.

The Mathematics of TF-IDF & Cosine Similarity

1. Term Frequency (TF): TF(t, d) = f(t, d) / ∑ f(t', d) 2. Inverse Doc Freq (IDF): IDF(t, D) = ln((1 + |D|) / (1 + |{d ∈ D : t ∈ d}|)) + 1 3. Vector Dot Product: Cosine_Similarity(A, B) = (A · B) / (||A|| · ||B||)
  • Term Frequency ($ ext{TF}$): Quantifies how frequently technical keywords (e.g., Kubernetes, Python, Django) appear in the resume text relative to document length.
  • Inverse Document Frequency ($ ext{IDF}$): Suppresses generic English stop-words (the, and, with) while amplifying domain-specific competencies.
  • Cosine Similarity: Measures the cosine of the angle between the multi-dimensional resume vector $ ec{A}$ and the job description vector $ ec{B}$, yielding a strictly bounded 0.0 to 1.0 mathematical match.
  • Google Gemini 2.5 Flash Layer: Analyzes contextual semantics that keyword vectors miss (e.g., understanding that "architected containerized microservices on AWS" fulfills "cloud infrastructure experience").
  • Weighted Composite Score: Merges mathematical and semantic scores, extracts hard and soft skill badges, and generates high-impact bullet rewrite suggestions.

9. 🎓 Comprehensive Viva Defense Cheat Sheet (Questions 1–8)

Q1: What is the primary problem CareerPilot solves in recruitment?
Answer: It solves the "visibility gap." Modern ATS systems discard over 75% of qualified resumes due to rigid keyword algorithms and parsing flaws. CareerPilot provides an objective hybrid ATS scoring engine, actionable keyword gap diagnostics, an ATS-compliant LaTeX resume builder, and an AI mock interview hub to accelerate placement readiness.
Q2: How does your hybrid scoring engine work under the hood?
Answer: We combine a deterministic scikit-learn TF-IDF vectorizer (calculating mathematical cosine similarity between candidate resume tokens and job description tokens) with Google's Gemini 2.5 Flash Generative AI (which analyzes contextual semantics, missing technical skills, and stream-specific keyword recommendations).
Q3: Where is your production application hosted, and how do you prove uptime?
Answer: It is actively deployed on an AWS EC2 t3.small instance (i-00f5712b6948b5092) in Mumbai (ap-south-1) with Elastic IP 15.252.51.16 and domain https://careerpilot.website. Visiting /metrics reveals app_uptime_seconds exceeding 280,000 seconds (78+ hours continuous uptime).
Q4: Why did you use multi-stage Docker builds?
Answer: Multi-stage builds separate the build environment from the runtime environment. For our React frontend (Dockerfile.frontend), Node.js and npm (~600MB) are discarded after compilation, copying only static assets into Nginx Alpine (~25MB), achieving a 95% image size reduction and minimizing security vulnerability attack surfaces.
Q5: What security practices are implemented in your backend Docker container?
Answer: In Dockerfile.backend, we compile C-extensions in a build stage and run the final container as an unprivileged, secure non-root user (careerpilot:1001). If the application is compromised, the attacker lacks root host privileges.
Q6: How does Kubernetes guarantee Zero-Downtime during updates?
Answer: In k8s/deployment.yaml, we declare a RollingUpdate strategy with maxSurge: 1 and maxUnavailable: 0. Kubernetes spins up a new pod with the latest code, waits for its /api/health readiness probe to pass, routes traffic to it, and only then terminates the old pod.
Q7: How does your infrastructure handle campus placement traffic spikes?
Answer: We implemented a Horizontal Pod Autoscaler (HPA) in k8s/hpa.yaml. When CPU utilization exceeds 70% or memory exceeds 80%, Kubernetes dynamically scales the backend Django pods from 2 up to 10 replicas across worker nodes.
Q8: Why did you choose Terraform for cloud infrastructure provisioning?
Answer: Terraform provides declarative Infrastructure as Code (IaC). Our 3-tier VPC (10.0.0.0/16), security groups, S3 buckets, and EC2 nodes are defined programmatically, eliminating 60+ manual console clicks, preventing configuration drift, and enabling repeatable environments.

When code is pushed to GitHub, Jenkins automatically detects the commit and executes 7 quality gate stages: Checkout, Parallel Lint, Django Check, React Build, Docker Build, Smoke Test, and automated SSH deployment to AWS EC2 (Build #7 100% Green).
Q11: Why does Prometheus use a Pull model instead of a Push model?
Answer: In a pull model, Prometheus controls the rate and schedule of data collection (every 10s). If application traffic surges 100x, it will not flood the monitoring server with pushed packets. Additionally, if the application crashes, Prometheus detects scrape failure immediately.
Q12: What is the difference between Prometheus and Grafana?
Answer: Prometheus is the backend metric scraper, storage engine (TSDB), and alert rule evaluator. Grafana is the visualization frontend that connects to Prometheus via PromQL queries and renders visual panels, dials, gauges, and time-series charts.
Q13: What business and ML metrics are visualized on your Grafana dashboard?
Answer: Beyond standard system uptime, Grafana visualizes domain-specific metrics: total resumes screened (resumes_analyzed_total), average ATS score (ats_score_avg), Google Gemini AI health percentage ((1 - errors/calls) * 100), and request traffic rates.
Q14: How does Linux swap memory protect your AWS EC2 instance?
Answer: Our t3.small instance has 2GB RAM. During heavy PDF parsing with NLP libraries, memory can spike. In ec2-userdata.sh, we allocated a 2GB NVMe swapfile, allowing the Linux kernel to swap idle memory pages to disk and preventing Out-Of-Memory (OOM) crashes.
Q15: How are credentials and API keys safeguarded throughout the lifecycle?
Answer: Following DevSecOps principles, .env files and .pem SSH keys are strictly excluded from Git via .gitignore and .dockerignore. Secrets are injected at runtime via Jenkins Credentials store and Kubernetes base64-encoded Secret objects.
